PIBO — GitHub Pages + Cloudflare R2

میزبانی سایت همچنان GitHub Pages است. فایل‌های مدل سه‌بعدی می‌توانند روی Cloudflare R2 باشند؛ هیچ بک‌اندی برای خود سایت لازم نیست.

تنظیم URL مدل برای هر محصول
1. فایل GLB و در صورت نیاز فایل USDZ را در باکت R2 آپلود کنید.
2. برای باکت، دسترسی عمومی با دامنه r2.dev یا دامنه سفارشی فعال کنید. برای سایت اصلی، دامنه سفارشی اختصاصی مثل assets.example.com مناسب‌تر است. هنگام آپلود، Content-Type مدل GLB را روی `model/gltf-binary` و USDZ را روی `model/vnd.usdz+zip` بگذارید.
3. تنظیمات CORS باکت را با محتوای cloudflare/r2-cors.json تنظیم کنید. اگر سایت از دامنه دیگری هم اجرا می‌شود، آن Origin را هم به AllowedOrigins اضافه کنید.
4. در پنل مدیریت، محصول را ویرایش کنید و URL کامل و عمومی فایل GLB را در «URL فایل GLB سه‌بعدی» قرار دهید. برای Quick Look آیفون، URL فایل USDZ را هم در فیلد مربوطه وارد کنید.
5. اگر برای سایزهای مختلف یا رنگ خمیر مدل جدا دارید، URLها را در بخش «عکس و مدل سه‌بعدی مخصوص این رنگ» همان سایز وارد کنید. URL سایز اولویت دارد و اگر خالی باشد، مدل سطح محصول استفاده می‌شود.
6. ذخیره کنید و سپس «انتشار مستقیم روی گیت‌هاب» را بزنید. بعد از تکمیل GitHub Pages deployment، صفحه را باز کنید و دکمه «مشاهده سه‌بعدی» را تست کنید.

نکات فنی
- فیلدها هم URL کامل https:// و هم مسیرهای نسبی قدیمی مثل models/name.glb را می‌پذیرند.
- مدل GLB از همان URL ثبت‌شده بارگذاری می‌شود؛ USDZ به Quick Look در دستگاه‌های اپل داده می‌شود.
- صفحه دیگر برای بررسی وجود فایل، کل فایل GLB را جداگانه دانلود نمی‌کند؛ این کار جلوی دانلود تکراری فایل‌های سنگین را می‌گیرد.
- باکت/فایل‌ها باید public باشند. URL خصوصی یا URL دارای امضای منقضی‌شونده برای لینک دائمی منو مناسب نیست.
- اگر از دامنه سفارشی GitHub Pages استفاده کردید، Origin آن را به CORS اضافه کنید.
- GitHub token فعلی فقط در localStorage همان مرورگری ذخیره می‌شود که پنل از آن استفاده می‌کند؛ آن را در کد یا فایل‌های مخزن قرار ندهید و فقط مجوز Contents: Read and write روی مخزن همین سایت بدهید.
